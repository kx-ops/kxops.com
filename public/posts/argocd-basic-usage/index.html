ArgoCD 简述及使用 下 —— 连接 GitHub、创建 App、版本回滚

May 8, 2026

上一篇 《Argocd 简述及使用 上》 介绍了 ArgoCD 的架构、核心概念和安装方法。本篇承接上文,讲三件最常用的事:

  1. 连接 GitHub 仓库(含私有仓库)
  2. 基于仓库里的 manifest 目录创建 Application
  3. 版本回滚 Rollback

一、准备工作#

假设你已按上一篇完成了 ArgoCD 安装。先确认服务在线:

kubectl get pods -n argocd

暴露 ArgoCD Server

本地测试最简单的方式是端口转发:

kubectl port-forward svc/argocd-server -n argocd 8080:443

浏览器打开 https://localhost:8080 即可访问 UI。

二、连接 GitHub 仓库#

ArgoCD 支持两种仓库连接方式:公开仓库(无需凭证)和私有仓库(需 SSH 或 HTTPS 凭证)。

方式 1:公开仓库(最简单)#

UI 操作:

  1. 左侧菜单 Settings → Repositories
  2. 点击 + CONNECT REPO
  3. 选择 VIA HTTPS
  4. 填写:
    • Type:git
    • Repository URL:https://github.com/你的用户名/你的仓库.git
  5. 点击 CONNECT,状态变为 Successful 即完成

CLI 方式:

argocd repo add https://github.com/kx-ops/manifests.git

方式 2:私有仓库(SSH Key)#

第 1 步:在本地或 Kubernetes 节点生成一对部署密钥

ssh-keygen -t ed25519 -C "argocd@k8s" -f ./argocd-deploy-key

生成两个文件:argocd-deploy-key(私钥)和 argocd-deploy-key.pub(公钥)。

第 2 步:把公钥添加到 GitHub 仓库

  1. 进入目标仓库 → Settings → Deploy keys
  2. 点击 Add deploy key
  3. 粘贴 argocd-deploy-key.pub 的内容
  4. 不要勾选 “Allow write access”(ArgoCD 只需读权限)
  5. 保存

第 3 步:在 ArgoCD 中添加仓库

UI:Settings → Repositories → + CONNECT REPO → VIA SSH

  • Repository URL:git@github.com:你的用户名/你的仓库.git
  • SSH private key data:粘贴 argocd-deploy-key(私钥)全部内容

CLI:

argocd repo add git@github.com:kx-ops/manifests.git \
  --ssh-private-key-path ./argocd-deploy-key

方式 3:私有仓库(Personal Access Token)#

适合公司场景或多仓库共用凭证。

  1. GitHub → Settings → Developer settings → Personal access tokens
  2. 生成 Token,勾选 repo 权限
  3. 在 ArgoCD 添加仓库:
argocd repo add https://github.com/kx-ops/manifests.git \
  --username kx-ops \
  --password ghp_xxxxxxxxxxxxxxxxxxxx

建议:生产环境优先用 SSH Deploy Key,粒度最细,只对单一仓库有效。

三、创建 Application#

假设你的 GitHub 仓库结构如下:

manifests/
├── nginx/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── ingress.yaml
└── redis/
    └── ...

我们要让 ArgoCD 部署 manifests/nginx/ 目录下的全部资源。

Web UI 创建#

  1. 首页点击 + NEW APP
  2. 填写基本信息:
字段填写值说明
Application Namenginx-demoApp 的名字
ProjectdefaultArgoCD 项目,默认即可
Sync PolicyManual / Automatic建议初次用 Manual
  1. SOURCE 部分:
字段填写值
Repository URLgit@github.com:kx-ops/manifests.git
RevisionHEAD(或具体分支、tag)
Pathnginx
  1. DESTINATION 部分:
字段填写值
Cluster URLhttps://kubernetes.default.svc(本集群)
Namespacedefault(或目标命名空间)
  1. 点击 CREATE
  2. 创建完成后,在 App 详情页点击 SYNC → SYNCHRONIZE 触发首次部署

声明式 YAML#

ArgoCD 本身就是 GitOps 工具,Application 定义也应该进 Git。创建 nginx-demo-app.yaml:

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: nginx-demo
  namespace: argocd
spec:
  project: default
  source:
    repoURL: git@github.com:kx-ops/manifests.git
    targetRevision: HEAD
    path: nginx
  destination:
    server: https://kubernetes.default.svc
    namespace: default
  syncPolicy:
    automated:
      prune: true       # Git 中删除的资源,集群中也同步删除
      selfHeal: true    # 集群中被手动修改的资源,自动恢复为 Git 状态
    syncOptions:
      - CreateNamespace=true

应用:

kubectl apply -f nginx-demo-app.yaml

状态查看#

argocd app get nginx-demo
argocd app list

UI 上会看到两个核心状态:

  • SYNC STATUS:Synced / OutOfSync — 集群状态是否与 Git 一致
  • HEALTH STATUS:Healthy / Progressing / Degraded — 应用是否正常运行

四、版本回滚 Rollback#

ArgoCD 的回滚非常直观:它把每次同步都视为一个 History 记录,可以一键回到任意一次历史版本。

前置条件:回滚功能要求 Sync Policy 设为 Manual,或在自动同步的 App 上临时禁用自动同步。否则 ArgoCD 会立刻把你的回滚"拉"回到 Git 最新版本。

第 1 步:查看历史版本#

UI:进入 App 详情页 → 顶部 HISTORY AND ROLLBACK 按钮

CLI:

argocd app history nginx-demo

输出示例:

ID  DATE                           REVISION
0   2026-05-08 09:20:14 +0800 CST  a1b2c3d
1   2026-05-08 10:15:32 +0800 CST  e4f5g6h
2   2026-05-08 11:40:08 +0800 CST  i7j8k9l  ← 当前

第 2 步:禁用自动同步(如启用了)#

argocd app set nginx-demo --sync-policy none

或 UI 上:APP DETAILS → SYNC POLICY → Disable Auto-Sync。

第 3 步:执行回滚#

UI:在 HISTORY AND ROLLBACK 列表中,找到目标版本,点击右侧菜单 → Rollback,确认即可。

CLI(回滚到 ID 为 1 的版本):

argocd app rollback nginx-demo 1

回滚完成后,UI 的 SYNC STATUS 会显示 OutOfSync,因为集群状态和 Git 最新版本不一致 —— 这是正常的,表明回滚生效了。

第 4 步:善后处理#

回滚只是临时止血,Git 才是唯一事实来源。确认回滚版本稳定后,应该:

  1. 在 Git 中 git revert 引发问题的 commit,或回退到好版本
  2. 恢复 ArgoCD 的自动同步策略:
argocd app set nginx-demo --sync-policy automated --auto-prune --self-heal

否则下次 App 被自动重新同步时,会又把你回滚的变更覆盖掉。

五、常见问题排查#

现象可能原因解决
仓库连接 FailedSSH Key 未加到 GitHub / URL 填成 HTTPS检查 Deploy Key,确认 URL 以 git@ 开头
App 一直 OutOfSync自动同步未开启 / Git 有新 commit手动 Sync 或开启 Auto-Sync
Rollback 按钮灰色App 处于自动同步模式先禁用 Auto-Sync
同步后资源不删除没开 prunesyncPolicy.automated.prune: true
集群资源被人手动改,ArgoCD 未恢复没开 selfHealsyncPolicy.automated.selfHeal: true

六、小结#

ArgoCD 的核心用法就三句话:

  • 连仓库:SSH Deploy Key 最稳,粒度最细
  • 建 App:声明式 YAML 写进 Git,别在 UI 点
  • 回滚:临时手段,根治还是要改 Git
