GitOps 基本知识入门笔记

GitOps 是一种基于 Git 仓库来管理 Kubernetes 集群和应用程序交付的现代化 DevOps 实践。核心是将 Git 作为基础设施和应用配置的“唯一源”，通过声明式（YAML）描述期望状态，利用 Git 的版本控制特性实现自动化拉取（Pull）和持续部署。主流工具为 Argo CD 和 Flux。 GitOps 的核心原则声明式： 通过 YAML 定义系统状态（如 Kubernetes 资源） 版本控制与不变性：所有状态变更记录于 Git，支持版本追踪 自动拉取：工具（如Argo CD）自动同步 Git 中的变更到集群 持续一致：实时监控实际状态与 Git 中期望状态是否一致 GitOps 工作流 提交 开发者将应用配置或 Kubernetes YAML 提交到 Git 存储库 触发 GitOps 控制器检测到 Git 仓库中的代码/配置更新 同步 控制器（如 Argo CD）将最新配置拉取到 Kubernetes 集群 协调 集群的实际状态与 Git 的期望状态自动对齐，不一致则自动修复 GitOps 的优势 高可观测性与合规性：Git 提交记录即为审计日志 回滚方便：出现问题时，使用 git revert 即可瞬间回滚到上一个稳定状态 安全性高：无需将 Kubernetes 集群凭证暴露给 CI/CD 系统 一致性：确保 Git 记录即生产环境状态 GitOps 历史 Git 是用于软件开发的关键任务工具，支持拉取请求和代码审查工作流程。拉取请求可提高代码库传入变更的可见性，并鼓励针对变更进行沟通、讨论和审查。 ...
